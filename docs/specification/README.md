# 設計・仕様ドキュメント インデックス

RPG『ポクポク』の設計・決定事項を機能ごとに記録する場所です。
(`.clinerules` の「ドキュメント管理」方針に従い、決定事項はコードではなくここに残します。)

## 文書一覧

| 文書 | 内容 | 状態 |
|---|---|---|
| [architecture.md](./architecture.md) | エンジン選定、レイヤ構成、依存ルール、テスト方針 | 作成済 |
| [ui.md](./ui.md) | 画面レイアウト、コンポーネント構成、カラーパレット、キーバインド | 作成済 (Phase 0 時点) |
| [assets.md](./assets.md) | ドット絵アセットの生成パイプラインとスプライト仕様 | Phase 1 で作成予定 |
| [map-system.md](./map-system.md) | タイルマップ、移動、エンカウント | Phase 2 で作成予定 |
| [battle-system.md](./battle-system.md) | コマンドバトル、ダメージ計算、属性弱点、敵AI | Phase 3 で作成予定 |
| [scenario-data.md](./scenario-data.md) | JSON データ構造、フラグ管理、イベント実行 | Phase 4 で作成予定 |
| [mcp-browser-debug.md](./mcp-browser-debug.md) | ブラウザ操作用 MCP 設定 (Cline 用) | 未作成 |

## 開発イテレーションの対応

`docs/design.md` の「段階的に実装する」方針に対応するフェーズ划分は次の通り。

1. **Phase 0** 基盤スクキャフォールド (Godot 導入 / テストランナー / ドキュメント)
2. **Phase 1** ドット絵アセット生成パイプライン
3. **Phase 2** マップ移動と UI のモック
4. **Phase 3** 戦闘システムの基礎
5. **Phase 4** データ読み込みとフラグ管理
6. **Phase 5** コンテンツ展開 (エリア1〜3 / 全10エネミー / 図鑑)
7. **Phase 6** Web エクスポート

## 記述ルール

- 各文書の先頭に「ステータス (確定 / 暫定 / 検討中)」を明記する
- 実装を変えたら文書も同じコミットで更新する
- UI に関する決定は必ず `ui.md` に記録する (`.clinerules` 規定)
